# Lab Video Learning Agent Rules

Краткий контракт для AI-агентов, работающих с лабораторной по классификации действий сотрудников.

## Read Order

1. Сначала читать `LAB6_FOUNDATION_RU.md`.
2. Затем проверять фактическое состояние `lab6/`, кода, артефактов и последних handoff-файлов, если они появятся.
3. Если факты в документах расходятся с артефактами, доверять артефактам и обновлять документы.

## Mandatory Subagents

Для каждого исследовательского или реализационного запроса использовать субагентов, если инструмент субагентов доступен в текущей среде.

Минимальный паттерн:

- один субагент собирает факты, ищет релевантные файлы, данные, ошибки или подтверждения;
- второй субагент выступает критиком: ищет утечки данных, переобучение, слабые допущения, невоспроизводимость и проблемы Docker/MPS;
- для крупных задач можно добавлять отдельного reviewer/debugger-субагента.

Главный агент всё равно отвечает за интеграцию результатов, проверку выводов и финальное решение. Если инструмент субагентов недоступен, явно написать это в ответе и вручную выполнить роли исследователя и критика.

## Project Constraints

- Задача: классификация 8 кадров в один класс: `inaction`, `move`, `work`.
- Финальный инференс должен принимать папку ровно с 8 изображениями и печатать один класс.
- Желательное время инференса на 8 изображений: до 10 секунд.
- Обучение ведётся на MacBook; локальный ускоритель по умолчанию `mps`.
- Финальное решение должно запускаться в Docker. Не считать MPS обязательным для Docker-инференса.

## Data Safety

- Не делить данные случайно по отдельным изображениям: кадры из одного трека не должны попадать одновременно в train и validation.
- Не использовать имена файлов, пути, EXIF/метаданные и порядок папок как признаки класса.
- Для длинных треков явно документировать стратегию: сэмплирование 8 кадров, sliding windows или последовательности переменной длины.
- Каждый новый эксперимент должен сохранять split, метрики по классам и confusion matrix.
